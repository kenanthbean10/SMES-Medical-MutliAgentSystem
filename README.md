git add README.md# SMES – Multiagent Healthcare Monitoring System

## Problem Domain
Real‑time patient heart rate monitoring with adaptive sampling, emergency detection, privacy preservation, and predictive analytics.

## Architecture
Decoupled JADE agents communicate via ACL messages (INFORM, REQUEST, CONFIRM, AGREE). Agents register and discover each other through the Directory Facilitator (DF) using service types (e.g., “vital‑sensing”, “gateway”, “decision‑making”, “power‑saving”, “medi‑notifier”, “shield‑guard”, “bio‑historian”). The system follows a pipeline:


**VitalSense → Gatekeeper → DecisionNode → (PowerSaver, MediNotifier, ShieldGuard) → BioHistorian**

- **VitalSense** – GUI sensor with auto‑ticker (adaptive sampling rate).
- **Gatekeeper** – validates HR (40–180 bpm), adds quality (GOOD/BAD) and status (NORMAL/WARN/DROP).
- **DecisionNode** – finite state machine (NORMAL / EMERGENCY / SENSOR_FAILURE) that orchestrates actions.
- **PowerSaver** – maps clinical state to sampling rate (LOW/MEDIUM/HIGH) and commands VitalSense.
- **MediNotifier** – prints emergency alerts with per‑patient cooldown (2 minutes).
- **ShieldGuard** – de‑identifies (stable pseudonyms) and encrypts (AES/CBC, IV prepended).
- **BioHistorian** – decrypts, computes real‑time analytics (trend slope, HRV, z‑score, 0‑10 risk score), and writes four output files.

## Output Files (generated by BioHistorian)
- `hil_store.txt` – encrypted audit log 
- `hil_analytics.txt` – every reading with risk score, slope, HRV
- `hil_alerts.txt` – predictive (trending tachycardia/bradycardia, high HRV) and reactive (sudden drop/rise) alerts, plus high‑risk reviews
- `hil_profiles.txt` – current summary of all patients 

## Agent Running  Order (Recommended)

Start the JADE **Main Container** first, then start the  agents in this sequence:

1. Main Container (RMA)
2. DecisionNode
3. Gatekeeper
4. PowerSaver
5. MediNotifier
6. ShieldGuard
7. BioHistorian
8. VitalSense
